# codegate

Шаблон настроек Claude Code, который задаёт жёсткий рабочий процесс разработки.
Рассчитан на команды, где junior–middle разработчики пишут код с помощью AI-агентов.

English version: [README.md](README.md).

## Что делает

Каждая задача проходит фиксированные фазы, пока код не попадёт в ревью:

0. **Старт** — задача = ветка: своя сессия, привязанная к этой ветке. Если в папке
   незаконченная работа, новая задача уходит в свой worktree.
1. **Elicitation** — агент сначала строит карту «кто читает и пишет данные задачи», потом
   присылает одно сообщение: как изменение встанет в систему (варианты, его выбор, нет ли
   решения проще или шире), не больше четырёх бизнес-вопросов с рекомендацией у каждого и
   мелочи, которые он решил сам. Косметические правки могут пройти по короткому пути
   (`/cg-approve quick`).
2. **Planning** — агент пишет план, затем детерминированный скрипт проверяет,
   что все упомянутые пути, символы и версии миграций действительно
   существуют, и предупреждает, если файл, который план собирается создать,
   уже носит имя существующего символа. Отдельный advisory-агент ищет в коде
   прежнюю реализацию — то, что уже делает работу, которую план предлагает
   написать заново, — и отмечает отклонения от принятых паттернов
   (HIGH-confidence из CODEBASE_CONTEXT.md).
3. **Implementation** — реализация по утверждённому плану, кусками, тест первым; каждый кусок
   делает суб-агент по файлам сессии.
4. **Quality gate** — сначала две механические проверки: покрытие (каждая
   новая осмысленная строка продового кода должна быть покрыта тестом) и
   ассерты (тест, которого коснулся дифф, обязан утверждать что-то, что может
   упасть — покрытие доказывает, что строка выполнилась, а не что кто-то
   заметил бы её ошибку). Затем LLM-ревью по нескольким измерениям, читающее
   файлы целиком, а не только дифф, с учётом baseline тестов и tech-debt.
5. **PR creation** — PR/MR с отчётом качества; связанные задачи в трекере для проектов-
   потребителей (фронт, мобилка) — после того как пользователь подтвердит черновики.
6. **После PR/MR** — находки QA, замечания ревью и правки CI — это *доработка*: та же ветка,
   перед пушем проверяются только новые коммиты. Дефект после мержа или расширение —
   новая задача, связанная с исходной.

В `CLAUDE.md` — только ядро (~6 тыс. символов); шаги каждой фазы — скилл
(`.claude/skills/cg-phase-N`), который подгружается при входе в фазу, а не уходит в каждый
вызов модели и каждому суб-агенту.

Хуки блокируют вызовы `Write` и `Edit` агента на неправильной фазе. Записи
через Bash (редиректы, `sed -i`) не перехватываются — это страховка, а не
песочница.

## Установка

Скопируйте в корень вашего проекта:

```
CLAUDE.md
.claude/
```

Добавьте в `.gitignore` (данные сессий эфемерные, контекст кода и tech-debt хранятся):

```
.ai/sessions/
.ai/current-session
.claude/worktrees/
```

Сессии ещё копируются в git-каталог репозитория (`.git/codegate/sessions/`), общий для
всех worktree, — удаление worktree не теряет его задачу.

Нужен Python 3 (стандартен на Linux/Mac) — используется хуками и скриптами
integrity/coverage.

## Использование

### Первый запуск в проекте

```
/cg-context
```

Анализирует проект, создаёт `.ai/CODEBASE_CONTEXT.md`, логирует существующие
проблемы в `.ai/tech-debt/`. Коммитьте `CODEBASE_CONTEXT.md`, чтобы у команды
был общий baseline.

### Начало задачи

```
/cg-feature  добавь фильтр по дате на страницу результатов
/cg-bugfix   пользователи не могут войти после сброса пароля
/cg-refactor вынеси логику оплаты в отдельный сервис
```

Ответьте на вопросы фазы elicitation и идите по подсказкам.

### Команды подтверждения фаз

```
/cg-approve quick           # принять fast-path для косметической правки (пропускает elicitation + planning)
/cg-approve elicit          # после ответов на вопросы elicitation
/cg-approve plan            # после ревью сгенерированного плана
/cg-approve implementation  # коммитит изменения, запускает coverage + ассерты + quality gate
/cg-approve quality         # override предупреждений уровня WARN
```

### Прочие команды

```
/cg-status   # задача этой ветки: состояние и следующий шаг
/cg-tasks    # все задачи репозитория: ветка, состояние, worktree
/cg-merged  # влит ли PR/MR задачи; если влит — закрывает задачу
/cg-next     # задачи из трекера, назначенные на вас, и какие из них уже начаты
/cg-debt     # список записанных tech-debt
/cg-resume   # продолжить задачу этой ветки после /clear, компакции или нового окна
```

### Трекер задач

Codegate не знает ни одного трекера. Он просит абстрактные действия — создать (в том числе в
другом проекте, со связью и ссылкой), получить, событие (`started`, `pr_created`, `merged`),
комментарий, связь, «мои задачи» — через `.claude/scripts/tracker.py` (договор в описании
скрипта). Отвечает на них адаптер проекта, в одном или двух видах: `.claude/tracker-adapter.py`
— скрипт; `.claude/tracker.md` — инструкция, как сделать действие инструментами, которые у ИИ
пользователя уже есть для этого трекера (MCP-сервер, CLI). Что скрипт не умеет, передаётся
агенту с этой инструкцией или пропускается. Настройки и ключи остаются у проекта. `/cg-start`
спрашивает, подключать ли трекер (`tracker`: `none` или `adapter`) и какие проекты потребляют
этот (`consumers`). Ещё он спрашивает, как запускается полный набор тестов (`test_command`):
процесс гоняет его до первой строки кода и в гейте качества; проекту, которому для этого
нужен свой скрипт, это задаётся здесь. Задача руками — `/cg-tracker`, назначенное на вас — `/cg-next`.

## Структура после установки

```
your-project/
├── CLAUDE.md                          # инструкции процесса (единственный источник правды)
├── .claude/
│   ├── settings.json                  # хуки + запреты
│   ├── hooks/
│   │   ├── pre-write.sh               # блок записи файлов до утверждения плана
│   │   ├── pre-push.sh                # блок git push до прохождения quality gate
│   │   ├── pre-agent.sh               # без задачи на ветке нет элицитации и плана
│   │   ├── task-context.sh            # к каждому сообщению — задача ветки и её состояние
│   │   ├── post-stop.sh               # копирует сессии в общее хранилище
│   │   └── post-compact.sh            # где стоит задача — на старте и после компакции
│   ├── skills/                        # cg-phase-0…5, cg-rework, cg-flow-feedback
│   ├── commands/                      # слэш-команды (cg-*)
│   ├── scripts/
│   │   ├── cg_session.py              # какая задача у этой рабочей копии; общее хранилище
│   │   ├── tracker.py                 # мост к трекеру (действия → адаптер проекта)
│   │   ├── plan-integrity.py          # проверка путей/символов/миграций (Фаза 2)
│   │   ├── test-assertions.py         # проверка «тест хоть что-то утверждает» (Фаза 4)
│   │   └── diff-coverage.py           # проверка покрытия (Фаза 4)
│   └── agents/                        # промпты суб-агентов
│                                      # (собственные тесты cg-core лежат в
│                                      #  core/tests/ и в проект НЕ ставятся)
│       ├── codebase-intelligence/     # /cg-context
│       ├── elicitation/               # Фаза 1 (включая триаж косметики)
│       ├── planning/                  # Фаза 2
│       ├── implementer/               # Фаза 3, один кусок плана, тест первым
│       ├── plan-review/               # Фаза 2, advisory-поиск прежней реализации
│       ├── quality-gate/              # Фаза 4
│       └── pr-creator/                # Фаза 5
└── .ai/                               # runtime-состояние
    ├── CODEBASE_CONTEXT.md            # коммитить
    ├── tech-debt/                     # коммитить
    └── sessions/                      # gitignored — эфемерные
```

## Требования

- Claude Code CLI
- Python 3 (для хуков и скриптов — стандартен на Linux/Mac)
- `git`
- `gh` или `glab` — опционально; без них создание PR вернёт ссылку для ручного оформления
